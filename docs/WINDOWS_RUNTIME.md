# Windows 缺失 UCRT 的修复

若启动时提示缺少 `api-ms-win-crt-runtime-l1-1-0.dll`，表示 Windows 加载器没有找到通用 C 运行库。v1.0.5 原始 Windows 便携包包含 VC++ 运行库，但漏带 UCRT；Windows 10/11 自带 UCRT，之前的测试未覆盖这个缺口。

## 修复现有 v1.0.5

关闭枝理，将 `枝理-v1.0.5-UCRT修复包-r1.zip` 解压。把其中 `运行库` 文件夹内的**全部 41 个 DLL**复制到原来的 `simplemap.exe` 同目录，再启动原来的程序。不要复制到 `System32`、`SysWOW64` 或仅复制到 `platforms` 文件夹；不需要改动导图或重新安装软件。

也可以使用补齐运行库的完整包 `ZhiLi-v1.0.5-Windows-x64-UCRT-fix1.zip`，解压到新的固定目录后运行其中的 `simplemap.exe`。原来的完整包和增量包保持不变，以免破坏已有校验值及增量升级基线。

补入 DLL 后的目录已不同于原始 v1.0.5 增量基线。以后升级建议直接使用新版完整包；若使用严格校验的增量更新器，应从保留的原版压缩包另行解压出基线目录，不要删除现用目录里的运行库来凑基线。

本次使用 Microsoft Windows SDK 再分发目录中的 x64 UCRT 10.0.10240.16384，包含 `ucrtbase.dll` 和整套 APISet 转发库。修复包附文件来源、SHA-256 清单。打包脚本今后会自动复制完整集合，并检查必需项、PE 架构和复制后的校验值。

## 验证边界

已针对缺失运行库进行文件、架构、签名和导入依赖检查，并在当前 Windows 系统进行便携启动检查。Windows 10/11 会优先使用系统 UCRT，因此在该系统启动成功**不能证明 Windows 7 真机通过**。目前没有可用的 Windows 7 SP1 x64 真机或虚拟机，本修复针对截图中的缺失 DLL 错误，不将 Windows 7 列为已全面验收的平台。

修复不改变 EXE、窗口身份、快捷方式和固定项；不安装全局运行库、不修改任务栏或系统图标缓存。如果移到新目录，旧固定项仍指向旧目录，请保留原目录并在那里应用修复，或由用户重新固定新目录入口。

微软建议通过系统更新部署 UCRT；初始更新为 KB2999226，也支持在应用目录部署完整 SDK 再分发集合。Windows 7 要求 SP1。[微软 UCRT 部署说明](https://learn.microsoft.com/en-us/cpp/windows/universal-crt-deployment)
