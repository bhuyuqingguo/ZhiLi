# Windows 与银河麒麟真机验收

本清单用于候选包验收。Linux x86_64 上的 Qt 自动化测试、虚拟缩放或文件结构检查，不能代替 Windows、银河麒麟和飞腾机器上的结果。未执行的项目标记为「未测」，不要填「通过」。

## 记录环境

- 包文件名、SHA-256、源码提交号。
- Windows 版本与补丁；或麒麟完整版本、补丁、内核、桌面会话。
- CPU 型号与架构、内存、显卡与驱动。
- 显示器分辨率、系统缩放、窗口是否最大化、多屏组合。
- Qt 运行库版本、中文输入法名称与版本。
- PowerPoint、Visio 或 WPS 的具体版本（涉及导出验收时）。

麒麟可记录 `uname -m`、`cat /etc/os-release`、`ldd --version`、`qmake -v`、`fc-match sans:lang=zh`。缺少 qmake 不等于缺少 Qt 运行库；以启动和 `ldd` 结果为准。

## 免安装启动

1. 用普通账户解压到中文路径与含空格路径，从文件管理器和终端各启动一次。
2. 断网后启动、编辑、保存、重开，确认没有要求登录或联网。
3. 在没有开发 SDK 的机器上运行。Windows 保留同目录 DLL 和插件；当前 Linux ARM64 包仍依赖兼容系统 Qt5，不要把它写成已验证的全自包含包。
4. 若缺少运行库，记录 `ldd` 输出，不要从不明网站下载 DLL/SO，也不要替换系统库。
5. 程序退出后删除解压目录，应不影响另行保存的 `.smap` 文件。便携包不等于所有设置都写在解压目录内。

## 核心编辑与数据保护

- 中文输入法：拼音候选、候选确认、连续输入、换行、Ctrl+Enter 确认、Esc 取消；候选确认不能误建主题或误结束编辑。
- Tab/Enter 建主题、F2 编辑、方向键选择、拖拽改父级和同层排序、撤销/重做。
- 长中文、emoji、空主题、1000 字以上段落：画布和导出不应静默截断。
- 复制/剪切/粘贴整棵分支，含折叠后代和图形符号。复制到新导图，再保存重开；原生剪贴板应保持原文。粘贴外部缩进文字时核对层级。
- 不允许删除中心主题或把祖先拖入自己的后代；失败操作不能改变数据。
- 编辑中保存、切换文件、关闭窗口；拒绝或取消操作后，文字和当前导图应保持。
- 保存到无写入权限目录或失效介质：原有文件不能损坏，未保存状态应保留。
- 异常结束后重新启动，接受与拒绝恢复各测一次。恢复后另存为，原文件应保留。
- 旧 `.smap` 文件、新增符号文件、中文路径文件跨平台往返。旧版枝理能忽略新符号字段，但再次保存可能丢掉符号，往返请使用同一候选版本。

## 显示、自动布局与性能

1. 实机覆盖 1366×768、1920×1080，以及手边的超宽屏；系统缩放覆盖 100%、125%、150%、200%。
2. 小窗口和大字号下检查菜单、工具栏、状态栏、对话框按钮、输入法候选窗，不能遮挡关键操作。
3. 从低缩放屏拖到高缩放屏，再移回；检查文字清晰度、点击坐标和窗口尺寸。
4. 关闭后重开，检查普通尺寸与最大化状态。拔掉原显示器后重开，窗口不能落在不可见区域。
5. 切换经典导图/结构图，新增、删除、移动、折叠后检查自动布局：主题不重叠、文字不出框、连接线指向正确。
6. 分别用 100、500、1000、3000 个主题，记录首次打开、布局切换、查找、缩放、拖动和保存耗时。至少重复三次，保留最慢值，不把云电脑数值当作飞腾性能。
7. 连续操作两小时，记录崩溃、卡顿、内存持续增长、输入丢失；出现问题时保留脱敏样例和复现步骤。

## 模板、素材与互通

- 从模板入口搜索并选择模板，预览与新建结果一致；取消不应覆盖当前未保存导图。
- 从素材入口按分类和关键词查找，添加/替换/移除符号；撤销、复制、保存重开和 PNG/SVG/PDF 输出一致。
- PowerPoint 导出：在目标 Office 版本打开，不应出现修复提示；逐页核对主题、层级和中文。拖动一个节点、修改一段文字，确认不是整页截图。检查大图分页和长文续页，不能漏掉折叠分支。
- 将 SVG 放入实际使用的 Visio/WPS/PowerPoint，检查中文、线条和符号。SVG 是图形交换，不等于 Visio 原生可编辑结构，也不证明 `.vsdx` 导入导出。
- 外部导图导入：保留原文件，核对主题数、顺序、层级、中文与导入警告。笔记、图片、关系线、任务等只有实际支持并验收后才能列为兼容。

## 结果记录

每个问题记录「操作 → 预期 → 实际 → 重现概率 → 环境 → 脱敏样例」。建议按阻断级别处理：

- P0：文件损坏、文字丢失、无法保存、无法正常启动。
- P1：关键编辑/导出无法完成、严重显示错位、常见操作卡死。
- P2：可绕过的布局、快捷键、菜单、素材显示问题。

正式发布前，P0 必须清零；P1 必须修复或明确限制。签名、再分发许可与发布审批另行检查。
